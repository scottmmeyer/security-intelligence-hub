# LMAT Recommendation Rationale Consistency Audit

**Date:** 2026-06-16  
**Status:** RESOLVED — Display-only fix applied (`ui/portfolio_alignment/app.js`, cache v28)

---

## Executive Summary

LMAT appears in the Capital Rotation Advisor as a **TAX_AWARE_EXIT** capital source. This classification is correct: LMAT has an unrealized loss of −$681 (market $6,894 vs. cost basis $7,575) and is being sold to fund higher-conviction purchases (SANM, MTZ, CRS).

The recommendation (Tax-Aware Exit, proceeds to fund rotation) is **correct**.

The displayed rationale ("Hold; do not prioritize for new cash") is also **correct as a UCF statement**, but **incorrect as a reduction rationale**. It describes LMAT's conviction stance, not the reason for its selection as a capital source.

Two different subsystems are generating outputs with two different intents:
- **CRA**: "Use LMAT as a tax-loss harvest source" (correct reduction context)
- **UCF**: "Hold LMAT; don't prioritize for new cash" (correct conviction context)

The UI was presenting the UCF statement as the reduction rationale, which reads as contradicting the sell recommendation. This is an **explainability defect, not a logic defect**.

## Part A — Recommendation Lineage

**Subsystem:** CRA (`src/portfolio/cra/capital_source_builder.py`)  
**Function:** `build_capital_sources()` → Category 4 (TAX_AWARE_EXIT) loop  
**File:** `src/portfolio/cra/capital_source_builder.py`, lines 500–556

### Decision chain:

```
1. LMAT holdings: market_value=$6,894, cost_basis=$7,575
2. unrealized = 6894 - 7575 = -$681.15 (LOSS)
3. _derive_tax_bucket(mv=6894, cb=7575, unrealized=-681.15)
   → bucket = "A"  (unrealized loss < 0)
   → annotation = "Unrealized loss ~$681 — tax loss harvest opportunity"
4. LMAT not in Cat 1/2/3 (not SIGNAL_DETERIORATION, not STRATEGIC_EXIT, not OVERWEIGHT)
5. bucket == TAX_BUCKET_A → create Category 4 record
6. sizing_pct = 1.0 (full position, _SIZING_FULL)
7. estimated_proceeds = $6,894
8. priority = "MODERATE" → upgraded to HIGH by Bucket A modifier
9. Category assigned: TAX_AWARE_EXIT
10. evidence_summary: "unrealized loss ~$681 | tax loss harvest opportunity"
11. reduction_reason: "Tax-aware posture supports harvesting this position before touching stronger conviction names."
```

**Result:** LMAT correctly enters the capital source pool as a TAX_AWARE_EXIT candidate with $6,894 in estimated proceeds.

### Deployment relationship:

## Part B — Rationale Lineage

**Subsystem:** UCF (`src/portfolio/unified_conviction.py`)  
**Function:** `_build_signal_summary()`  
**Template (TACTICAL_GROWTH tier):**

```python
f"{symbol} — Tactical growth: {sig} signal, composite {comp_str}{replay_note}. "
f"Hold; do not prioritize for new cash."
```

**Source:** This string is generated by UCF's conviction synthesis layer. For TACTICAL_GROWTH holdings, it means: "This position has moderate signal support but insufficient replay coverage and conviction tier to warrant capital deployment. Retain as a position but do not deploy new cash to it."

**UI rendering bug (pre-fix):** `ui/portfolio_alignment/app.js` line 5531:
```javascript
const sigSummary = ucf.signal_summary || s.evidence_summary || "";
if (sigSummary) { rationale = sigSummary; }
```

The UI used `ucf.signal_summary` first, discarding the CRA-specific `reduction_reason` entirely. Since LMAT has a UCF entry with a TACTICAL_GROWTH signal_summary, that string became the reduction rationale — even though it describes conviction stance, not reduction reasoning.

## Part C — Recommendation vs Rationale Consistency

| Item | Source | Intent | Correct? |
|------|--------|--------|---------|
| Tax-Aware Exit | CRA (capital_source_builder.py) | This position has a loss → sell to harvest | **Yes — correct CRA output** |
| Suggested Weight 0.00% | UI (renderReductionQueue) | Full position exit = 0% remaining | **Yes — sizing_pct=1.0 means full exit** |
| Executable | CRA (not blocked_by_policy) | No operator policy blocks this exit | **Yes — no DO_NOT_SELL policy** |
| "Hold; do not prioritize for new cash" | UCF (unified_conviction.py) | Don't deploy NEW capital to LMAT | **Yes — correct UCF conviction stance** |
| **Displayed as reduction rationale** | UI (rationale assignment bug) | **Wrong context — UCF statement ≠ reduction reason** | **DEFECT** |

**Does "Hold; do not prioritize for new cash" conflict with "Tax-Aware Exit"?**

No — these are answering different questions:
- "Hold" = UCF's view on whether to ADD new cash to LMAT
- "Tax-Aware Exit" = CRA's view on whether to use existing LMAT position as a rotation source

A holding can simultaneously be:
1. Worth retaining (UCF: TACTICAL_GROWTH, moderate conviction)
2. Suitable as a rotation funding source (CRA: unrealized loss, tax harvest opportunity)

These are not contradictory. The defect was the UI presenting the UCF retention statement as if it were the reason for the sale.

## Part D — Tax-Aware Exit Analysis

| Field | Value |
|-------|-------|
| Market value | $6,894.00 |
| Cost basis | $7,575.15 |
| Unrealized gain/loss | **−$681.15 (LOSS)** |
| Tax bucket | **A** (loss harvest candidate) |
| Tax annotation | "Unrealized loss ~$681 — tax loss harvest opportunity" |
| Category | TAX_AWARE_EXIT |
| Sizing | 100% (full position, $6,894) |
| Priority | MODERATE (upgraded from MODERATE by Bucket A modifier) |

**Why Bucket A triggers full-size exit:** The CRA does not apply partial sizing to loss-harvest positions. Bucket A positions use `_SIZING_FULL = 1.0` because the tax benefit is proportional to the full loss realization.

**Would LMAT still appear if tax-aware logic were disabled?**

**No.** LMAT's opportunity_flag is HOLD, not TRIM. It is not overweight (is_overweight_vs_target=False). It is not in Category 1 (SIGNAL_DETERIORATION), Category 2 (STRATEGIC_EXIT), Category 3 (OVERWEIGHT_REDUCTION), or Category 5 (LOW_CONVICTION_REDUCTION, which requires HOLD flag AND not in deployment queue AND below de minimis). Without Bucket A qualification, LMAT would not appear in any capital source category.

Tax-aware logic is the sole driver of LMAT's source status.

## Final Verdict

| Q | Answer |
|---|--------|
| Q1: Why is LMAT classified as Tax-Aware Exit? | Unrealized loss of −$681 (Bucket A) triggers Cat 4 TAX_AWARE_EXIT with full-position sizing. |
| Q2: Why does LMAT receive Suggested Weight = 0.00%? | sizing_pct=1.0 (full exit). Market value after full sale = $0. No residual weight. |
| Q3: What subsystem generated the recommendation? | CRA (`capital_source_builder.py` Category 4). |
| Q4: What subsystem generated the rationale? | UCF (`unified_conviction.py`, `_build_signal_summary()`, TACTICAL_GROWTH template). |
| Q5: Does the rationale support the recommendation? | **Not directly.** UCF rationale describes conviction stance; CRA recommendation is tax-driven. They address different questions and are both correct. |
| Q6: Is the recommendation behaving correctly? | **Yes.** LMAT has a $681 loss → Bucket A → TAX_AWARE_EXIT. No defect in CRA logic. |
| Q7: Is the rationale behaving correctly? | **Yes.** UCF correctly classifies LMAT as TACTICAL_GROWTH and says "Hold." The defect was the UI using this as the *reduction* rationale. |
| Q8: Is this a recommendation defect, rationale defect, or explainability defect? | **Explainability defect.** Both the recommendation and rationale are correct in their own contexts; the UI was conflating them. |
| Q9: Would LMAT still appear as a funding source if tax-aware logic were disabled? | **No.** LMAT has HOLD flag, no overweight, no signal deterioration. Without Bucket A, no source category applies. |
| Q10: Is a logic change required? | **No.** CRA, PAP, UCF, CW-DAS, and ESS are all operating correctly. |
| Q11: Is a display-only change required? | **Yes.** Rationale assignment priority in `renderReductionQueue()`. |
| Q12: What exact remediation was applied? | UI fix in `renderReductionQueue()`: use CRA `reduction_reason`/`evidence_summary` as the primary rationale, then show UCF `signal_summary` as a clearly labeled "UCF Conviction" context block explaining the conviction vs. rotation distinction. |
