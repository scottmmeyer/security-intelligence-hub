# Phase 23.0A.1 — Q3: Cost Basis Dependency Audit

**Validation Question**: Which tax-aware features are unavailable without cost basis data? Is SIH functional without it?

---

## Data Field Requirements by Feature

### Fields Required for Full Tax Feature Fidelity

| Field | Source | Used For |
|---|---|---|
| `cost_basis` | Portfolio export (optional) | Unrealized G/L calculation |
| `market_value` | Portfolio export (optional) | Unrealized G/L calculation |
| `holding_days` | Portfolio export (optional) | LT/ST classification |
| `ess_direction` / `signal_direction` | SIH analysis pipeline (always present) | Bucket A, B, C, D, E assignment |
| `recommended_action` | SIH analysis pipeline (always present) | Bucket A, C, D assignment |
| `cw_das_flag` | SIH analysis pipeline (always present) | Bucket E assignment |

Signal fields are always produced by `run_analysis()` and are always present in `security_overlays`. Cost basis fields are optional portfolio export fields not generated by SIH.

---

## Fidelity Tiers

### Tier 1 — FULLY AVAILABLE WITHOUT COST BASIS

These features operate entirely from signal/flag data:

**Bucket A (signal-only path)**
```js
// Check 5 in _computeTaxActions():
} else if (isPoorOutlook && unrealizedGL == null) {
  bucket = "A"; timing = "SELL_NOW";
  reason = "Poor outlook — cost basis unavailable for tax calculation";
}
```
Poor-outlook holdings are surfaced for review regardless of cost basis. Action is SELL NOW with a disclosure that gain/loss status is unknown.

**Bucket C (reduce candidate)**
```js
} else if (isReduceCandidate) {
  bucket = "C";
  timing = unrealizedGL != null && unrealizedGL > 0 ? "SELL_NOW" : "HARVEST_LOSS";
  reason = "Mandate drift / reduce candidate";
}
```
When `unrealizedGL == null`, `timing = "HARVEST_LOSS"` is the fallback. This is a mild misnomer without gain data — a future enhancement should use "SELL" without loss-harvesting language when cost basis is absent.

**All bucket labels, priority numbering, reasoning column, signal column**

These are all derived from SIH analysis fields which are always populated.

---

### Tier 2 — PARTIALLY AVAILABLE WITHOUT COST BASIS

These features degrade gracefully to a neutral placeholder:

| Feature | With Cost Basis | Without Cost Basis |
|---|---|---|
| Tax Impact column | `+$14,230` or `-$8,450` | `—` |
| Tax Category column | "Long-Term Gain", "Short-Term Gain", "Capital Loss" | "N/A" |
| Holding Period column | `180d (ST)`, `420d (LT)` | `—` |
| Bucket D / Harvest Loss | Full: detected via unrealized loss | Absent: cannot harvest unknown loss |
| Bucket B / Wait | Full: detected via ST gain + poor outlook | Absent: cannot classify short-term |
| Bucket E / Hold Despite Gain | Full: confidence + gain context | Partial: shows E but no gain amount |

---

### Tier 3 — UNAVAILABLE WITHOUT COST BASIS

| Feature | Why Unavailable |
|---|---|
| Bucket D (Harvest Loss assignment) | Requires `unrealizedGL < 0`, which requires cost basis |
| Bucket B (WAIT assignment) | Requires `unrealizedGL > 0` AND `isLongTerm === false`, both require cost basis fields |
| `gainShielded` comparison | Requires `unrealizedGL` to compare against `available` — without it, shielded-gain path (Bucket A) never fires |
| Partial gain shield advisory | Requires `unrealizedGL` to compare against available capacity |

## Export Format Compatibility

### Fidelity CSV (Broker-Connected Export)
Contains all fields including `cost_basis`, `market_value`, `holding_days`. Full Tier 1 + Tier 2 features active.

### Generic Portfolio CSV (Manual Entry Export)
`cost_basis` is optional. If omitted, features degrade to Tier 1 only. SIH continues to function — tax column renders with `—` placeholders where data is absent. No errors are thrown.

### JSON Analysis Result (API Response)
`security_overlays` in the API response carries whatever fields the portfolio ingestion pipeline populated. If portfolio file had no cost basis columns, those fields are absent from overlays. `_computeTaxActions()` handles absence via `parseFloat(ov.cost_basis ?? "") → isNaN → hasGainData = false`.

---

## No Hard Dependencies on Cost Basis

The core portfolio analysis pipeline (`POST /api/portfolio/analyze` → `run_analysis()`) does not require or use cost basis data. The tax feature reads cost basis purely from the existing `security_overlays` data that is returned in the analysis result. No separate API call is made for cost basis.

SIH is fully functional as a signal intelligence platform without cost basis. The tax feature adds context when cost basis is available, and degrades gracefully when it is not.

---

## Operator Communication

When cost basis is absent, the Tax Action table footer reads:

> "Tax impact derived from cost basis in portfolio export when available. Holding period estimated from portfolio data when present."

This is passive disclosure. A future enhancement could add an explicit panel-level notice: "Cost basis not detected in this portfolio export — tax impact and holding period unavailable."
