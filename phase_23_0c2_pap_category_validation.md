## 4. Category 3 — Allocation Reduction

### 4.1 Candidate Selection Logic

Source: `data.recommendations` filtered to `recommendation_type === "REDUCE_OVERWEIGHT"`.

**Mapping:** Each `REDUCE_OVERWEIGHT` recommendation carries an `affected_symbols` array. Each symbol in that array becomes a Cat3 candidate linked to its parent node.

**Severity assignment:**
- `HIGH` if `Math.abs(drift_pct) >= 5`
- `MEDIUM` if `Math.abs(drift_pct) < 5`

**Protection flag:** `_PROTECTED_CONVICTION_TIERS` holdings ARE included but marked `is_protected: true` (they appear in Cat3 as a display-only advisory; the operator retains discretion).

**Sort:** by `drift_pct` descending.

**Exclusion filters (any excludes):**
1. Symbol in `_PROTECTED_CONVICTION_TIERS` (HIGH_CONVICTION_ANCHOR, CORE_CONVICTION_LEADER)
2. `pct < 0.05` (position too small to be a meaningful funding source)
3. `composite_score == 0` (no signal data)

- `HIGH` if symbol is in Cat1 (`SIGNAL_DETERIORATION`)

## 7. Candidate Generation vs. Ranking

**Candidate generation** (inclusion/exclusion decisions) is governed entirely by:
- Signal fields in `security_overlays.csv`: `opportunity_flag`, `signal_direction`, `ess_score_text`
- Recommendation type filter (`REDUCE_OVERWEIGHT`) and `affected_symbols` in `recommendations.json`
- Operator-configured `_strategicExitSymbols` array
- Conviction tier from `deployment_queue.json` (exclusion only)
- Portfolio weight from overlays: `percent_of_portfolio`

**Ranking/ordering** (sort position within category) is governed by:
- Priority (HIGH/MEDIUM/LOW) — computed from signal strength or drift magnitude
- `composite_score` — ascending (within priority tier, weaker signals surface first)
- `drift_pct` — descending (larger allocation violations surface first in Cat3)

Tax state (`_taxState`) plays no role in candidate generation or ranking. This is confirmed by code inspection: `_computePortfolioActions(data)` references `_taxState` zero times.
