**Date:** 2026-06-09

## What Is "Recommended Actions — Top 10"?

The label appears in the Deployment Queue section of Portfolio Alignment. It is rendered by the function `_daRenderActionCards()` in `ui/portfolio_alignment/app.js`.

---

## Trace

### Step 1: Entry Point

`renderDeploymentQueue(data)` — line 3634 of `app.js`

```javascript
const actionCardsHtml = hasPlan
    ? _daRenderActionCards(queue, _dpBySymbol, 10)
    : `<div class="da-no-plan-hint">No deployment plan loaded…</div>`;
```

`hasPlan` is true only when a deployment plan has been generated on demand (via "Generate Deployment Plan" button). The "Top 10" only shows after this on-demand step.

### Step 2: `_daRenderActionCards(queue, dpBySymbol, limit=10)`

**Source:** `app.js` line 3933

```javascript
const planRecs = Object.values(dpBySymbol)
    .sort((a, b) => a.rank - b.rank)
    .slice(0, limit);
```

`dpBySymbol` is built from `data.deployment_plan.recommendations` — the output of the deployment planning step (see Step 3).

### Step 3: Data Source — `deployment_plan.recommendations`

The deployment plan is generated by `src/portfolio/deployment_planner.py` (called via `/api/portfolio/deployment-plan`). It takes:
- `deployable_cash` — excess cash above mandate floor
- `deployment_queue` — the CW-DAS ranked list of BUY candidates

It allocates available cash to DQ candidates in rank order. Each candidate gets a `suggested_add` (USD amount) and a `rank`.

### Step 4: `_daRenderActionCards` rendering

```javascript
return `<div class="da-action-card${rankBadge}">
    <div class="da-card-header">
        <span class="da-card-action">BUY</span>  ← HARDCODED STRING
        <span class="da-card-sym">${escHtml(sym)}</span>
```

**The string "BUY" is hardcoded.** There is no conditional logic that would render "TRIM", "SELL", or "REDUCE" as the action type, regardless of what signals the symbol has.

## Filtering Logic

The "Top 10" is filtered at **three upstream gates** before any rendering occurs:

### Gate 1: DQ Eligibility (`_is_eligible()`)

```python
if (overlay.signal_direction or "").upper() != "BULLISH":
    return False
if not overlay.replay_supported:
    return False
if profile.strategic_classification != "HIGH_CONVICTION_RETAIN":
    return False
if profile.narrative_tier not in _ELIGIBLE_TIERS:  # CCL or HCA only
    return False
```

**Effect:** Only BULLISH, replay-supported, HIGH_CONVICTION_RETAIN, CCL/HCA holdings enter the DQ. Any BEARISH holding is structurally excluded.

### Gate 2: Policy Filtering

`apply_policy_to_queue()`: DO_NOT_SELL holdings are moved to `policy_suppressed`, not the `queue`. They never appear in Top 10.

### Gate 3: Deployment Plan Allocation

Only holdings with `suggested_add > 0` appear as action cards. Holdings with insufficient cash allocation receive `suggested_add = 0` and do not get cards.

## Sell/Trim/Rotation Eligibility in Top 10

| Action Type | Can Appear in Top 10? | Why Not |
|---|---|---|
| BUY | Yes | Only type rendered |
| ACCUMULATE | No label — shown as BUY | Same rendering path |
| TRIM | **No** | BEARISH signals excluded by DQ eligibility gate |
| SELL | **No** | BEARISH signals excluded by DQ eligibility gate |
| REDUCE | **No** | REDUCE recs exist in PAP but have no path to DQ/Top10 |
| ROTATE | **No** | CRA rotation proposals have no path to Top 10 |

---

## Summary

The "Recommended Actions — Top 10" is:
1. **Populated exclusively from the Capital Deployment Queue (CW-DAS)**
2. **The CW-DAS queue admits only BULLISH, HIGH_CONVICTION_RETAIN, replay-supported holdings**
3. **The action label "BUY" is hardcoded in the rendering function**
4. **No TRIM, SELL, REDUCE, or ROTATE action can appear here under any current code path**

This is functionally a "Top 10 Buys" list presented under the label "Recommended Actions."
