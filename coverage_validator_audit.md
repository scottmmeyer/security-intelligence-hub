# ESS Coverage Validator Audit

Date: 2026-06-17  
Scope: Determine why UI reports "55 holdings absent" and whether count is accurate

## Validator Implementation Path

Coverage warning generation is implemented in:
- src/portfolio/ess_coverage.py: build_ess_coverage_gap_warning()
- called by src/pipeline/stages/ess_intake_stage.py during ESS intake

## Comparison Sets Used by Validator

Expected universe:
- load_latest_equity_holdings(analysis_runs_root)
- source: latest PAR directory with name prefix PAR-2, then holdings.csv equities only

Actual incoming ESS universe used for pass condition:
- incoming_ess_symbols from ess_intake_stage.py
- generated by _incoming_ess_symbols(normalized_signal_records)
- strict inclusion rule: symbol is counted only if
  - coverage_domain == STARMINE_COVERED
  - starmine_ess_text is non-empty

Prior ESS reference set:
- load_fidelity_signals(data/current/signal_snapshot.csv)
- only symbols with non-empty ESS text are retained

## Exclusion Rules (Observed)

A holding is flagged as missing when all are true:
1. holding symbol not in incoming_ess_symbols (strict StarMine+ESS-text gate)
2. symbol exists in prior_ess map (has historical ESS text)
3. holding appears in latest holdings baseline used at warning time

This excludes non-ESS rows from being treated as coverage, even when symbol is present in current cycle input/partitions.

## Why 55 Appears

Current warning payload (data/current/ess_coverage_warning.json):
- warning_count: 55
- examples: MU, FIS, VRT

But artifact trace shows MU and VRT are present in:
- incoming ESS files
- parsed partition outputs
- merged current signal snapshot
- current overlay output

Therefore the warning count is not a pure data-loss count. It is a validator-logic count based on strict incoming StarMine ESS-text criteria.

## Accuracy Assessment

Is "55 missing holdings" accurate as data loss?  
- No. It is a false positive for symbol disappearance/loss.

Is "55 lacking fresh StarMine ESS in validator's run-local comparison" potentially accurate?  
- Possibly, depending on the specific intake run context and timing.

Practical interpretation:
- The reported 55 does not mean symbols disappeared from the signal pipeline.
- It reflects validator comparison logic and run-context assumptions.

## Additional Observed Timing Drift

FIS appears in warning payload but is absent from latest PAR-20260617-001280E0 overlay working set, indicating warning payload and current overlay/API working set are not guaranteed to be synchronized to the same holdings snapshot moment.

## Verdict

The health panel value "55 holdings absent" is a reporting/validation defect for coverage-loss interpretation, not evidence of broad ESS ingestion or merge loss.
